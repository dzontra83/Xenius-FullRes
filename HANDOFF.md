# Hand-off — Xenius-FullRes (state on 2026-11-26, build P290)

Read this first when continuing the project in a new chat/account.

## The project
GCam port **Xenius** (LMC 8.3 based, package `com.meitu.xenius135a01`) patched for the **vivo X300 Ultra** to shoot
**50 MP and 25 MP through HDR+** (native quad sensor mode + our own remosaic + our own burst merge).
Patching is done **without apktool/smali**: Python scripts edit the dex bytecode directly and generate an extra
`classes3.dex` (helper `TemporalBinning` and small classes) plus a native `lib/arm64-v8a/libtbin.so`.

## How to build (needs the base APK)
The base APK **`XENIUS_P174B_UNSIGNED.apk` is NOT in the repo** — ask the owner to upload it.
```bash
cd rebuild/P290
export PYTHONPATH=../P149A:../P149B:../P163:../../tools/dex
OISB=off SETTLE=200 python3 build_p290.py XENIUS_P174B_UNSIGNED.apk XENIUS_P290_UNSIGNED.apk
OISB=off SETTLE=200 TBLOG=1 python3 build_p290.py XENIUS_P174B_UNSIGNED.apk XENIUS_P290L_UNSIGNED.apk
```
New builds: copy `rebuild/P290` to `rebuild/P<next>`, rename the build script (sed the version), change, build.
`libtbin.so` (freestanding: no libc / libm — own memset/memcpy, own sin, no malloc in the phone build):
```bash
clang --target=aarch64-linux-android29 -O3 -fPIC -ffreestanding -fno-builtin -nostdlib -shared -fuse-ld=lld \
  -fvisibility=hidden -Wl,-soname,libtbin.so -Wl,-z,now -Wl,--hash-style=both -s -o libtbin.so tbin.c
```
Host tests: `tp288.c` (8-frame synthetic quad burst, `-DPM_FORCE0`, `-DMOT=1` motion set), `bandsT.py truth.raw out.raw`
(detail response / noise per frequency band), `ghost.py`. Test data is generated by `test_merge/gen*.py`.

## Architecture
- `build_p290.py` hooks: `Llei` (burst callback), `Lleu.onImageAvailable` (50 MP frame arrived -> next paced capture),
  `Ldvm.o` (register the shot's raw frames for the pre-merge), `Llet.<init>` (frame -> native remosaic), `Ohv.k`
  (noise model, HDR ratio cap), `AeShotParams.g` (night key: shot EV via helper), LMC prefs/UI (RES 12/50/25,
  remosaic button XR/ER/SR, double-tap dialog), GCam's file-name format (tag), shutter progress overlay.
- Cross-dex calls from classes.dex: `Class.forName("getWidth").newInstance()` is a Comparator; `compare(arg, null)`
  dispatches by type (Integer codes = profiles / shutter-tap log, SimpleDateFormat = file tag wrapper, Float = night
  key EV, other object = shutter overlay).
- **Beware when editing dexgen.py:** registers are hand-allocated; a VerifyError makes the whole helper class fail and
  the app silently behaves like plain GCam (symptom: log has only `noise model scaled` lines).
- libtbin: `quad.c` remosaic (ER = Ed's Detail port; XR = own; bin mode), `merge.c` pre-merge (registration of all
  raw frames, remosaic each, sharpest = reference, tile alignment + affine field, frequency-domain merge, finish,
  copy into every frame; 25 MP: demosaic -> Lanczos-3 -> remosaic), `natural.c`.

## What the logs taught us (vivo HAL / GCam)
- Full-size requests: keep **6 in flight** (`PACE`); 10 at once -> failed frames, closed session. Sending them as
  `captureBurst` lists (P289 test) gave 40 ms spacing for one chunk, then failed frames, extra images and an
  ImageReader overflow crash -> keep single requests, one sent per arriving frame.
- First 50 MP burst after an app start sometimes got no frame and the HAL closed the session; the 1-frame warm-up
  (P287, `WARM1`) fixed it in tests.
- 60 ms frames without OIS stalled a burst -> steady cap 40 ms; night (OIS on) up to 60 ms.
- GCam re-normalises brightness from the frames: lower ISO frames come out at the same brightness (scaling the merge
  output darker also fails). Changing GCam's own shot EV (`AeShotParams.g`) does change the result (night key).
  `AeShotParams.g` is also called every ~200 ms for the viewfinder.
- Viewfinder surfaces on still requests -> HAL fails every frame (mixed sensor pixel modes). Viewfinder freeze at the
  shutter is the sensor mode switch; SCAMERA avoids it by running the whole session in 50 MP mode (not portable).
- GCam's exposures are 10 ms multiples (50 Hz anti-banding); ours too (`BAND`).
- RAW10 50 MP frames from this HAL in quad mode are empty (all zeros) -> RAW16 only.
- HDR ratio cap 1.5 = natural tone; 2.0 changed little on lamps (the clipping was the light sources).
- Merge: frequency-domain merge (P288F) vs spatial merge on the phone: 16-28 % less fine noise, crisper edges,
  +0.6 s per 10-frame 25 MP merge.

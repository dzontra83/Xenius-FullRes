# Hand-off — Xenius-FullRes (state on 2026-11-27, build P330)

Read this first when continuing the project in a new chat/account.

## The project
GCam port **Xenius** (LMC 8.3 based, package `com.meitu.xenius135a01`) patched for the **vivo X300 Ultra** to shoot
**50 MP and 25 MP through HDR+** (native quad sensor mode + our own remosaic + our own burst merge).
Patching is done **without apktool/smali**: Python scripts edit the dex bytecode directly and generate an extra
`classes3.dex` (helper `TemporalBinning` and small classes) plus a native `lib/arm64-v8a/libtbin.so`.

## How to build (needs the base APK)
The base APK **`XENIUS_P174B_UNSIGNED.apk` is NOT in the repo** — ask the owner to upload it.
```bash
cd rebuild/P330
export PYTHONPATH=../P149A:../P149B:../P163:../../tools/dex
OISB=off SETTLE=200 python3 build_p330.py XENIUS_P174B_UNSIGNED.apk XENIUS_P330_UNSIGNED.apk
OISB=off SETTLE=200 TBLOG=1 python3 build_p330.py XENIUS_P174B_UNSIGNED.apk XENIUS_P330L_UNSIGNED.apk
```
New builds: copy `rebuild/P330` to `rebuild/P<next>`, rename the build script (sed the version), change, build.
`libtbin.so` (freestanding: no libc / libm — own memset/memcpy, own sin, no malloc in the phone build):
```bash
clang --target=aarch64-linux-android29 -O3 -fPIC -ffreestanding -fno-builtin -nostdlib -shared -fuse-ld=lld \
  -fvisibility=hidden -Wl,-soname,libtbin.so -Wl,-z,now -Wl,--hash-style=both -s -o libtbin.so tbin.c
```
Host tests: `tp288.c` (8-frame synthetic quad burst, `-DPM_FORCE0`, `-DMOT=1` motion set), `bandsT.py truth.raw out.raw`
(detail response / noise per frequency band), `ghost.py`. Test data is generated by `test_merge/gen*.py`.

## Architecture
- `build_p330.py` hooks: `Llei` (burst callback), `Lleu.onImageAvailable` (50 MP frame arrived -> next paced capture),
  `Ldvm.o` (register the shot's raw frames for the pre-merge), `Llet.<init>` (frame -> native remosaic), `Ohv.k`
  (noise model, HDR ratio cap and short-exposure EC from props), `Lkxc.p` (request keys: centre AF region, AF mode, face detection), `Lmpz.run` (GCam's ProcessReaper, disabled), `AeShotParams.g` (night key: shot EV via helper), LMC prefs/UI (RES 12/50/25,
  remosaic button ER/SR, Advanced > Disable face detection, double-tap dialog), GCam's file-name format (tag), shutter progress overlay.
  P310+: `Llet.<init>` also hands every RAW16 frame to the AE meter (`Pair`); DLock `a(String)` (config load) calls
  helper code 95; LMC `Aperture` button = XML loader (`Aperture$1.onCheckedChanged` -> code 93 -> `LTBXL.show`,
  added to `OpenPref.initFabMenu`, `UpdateUi` fixed to state 0, layout instance hidden); `Upscale.init` -> code 94 (toast).
- Cross-dex calls from classes.dex: `Class.forName("getWidth").newInstance()` is a Comparator; `compare(arg, null)`
  dispatches by type (Integer codes = profiles 0..12 / 99 commit / 98 import restart / 97,96 shutter-tap log /
  95 import selected / 94 import toast / 93 XML list, SimpleDateFormat = file tag wrapper, Float = night
  key EV + HDR cap + short EC into props, Integer AF mode from Lkxc.p, other object = shutter overlay).
- **Beware when editing dexgen.py:** registers are hand-allocated; a VerifyError makes the whole helper class fail and
  the app silently behaves like plain GCam (symptom: log has only `noise model scaled` lines). The `getWidth` class is
  loaded at UI start since P316 (code 94), so a VerifyError there now crashes the app at launch (P316: a register that
  was String on one path and Object on another -> add check-cast). No verifier here: review merge points by hand.
- libtbin: `quad.c` remosaic (ER = Ed's Detail port; mode 2 = copy for vivo-remosaiced SR 25 MP frames; bin mode), `merge.c` pre-merge (registration of all
  raw frames, remosaic each, sharpest = reference, tile alignment + affine field, frequency-domain merge, finish,
  copy into every frame; 25 MP: demosaic -> Lanczos-3 -> remosaic), `natural.c`.

## What the logs taught us (vivo HAL / GCam)
- Full-size requests: keep **6 in flight** (`PACE`); 10 at once -> failed frames, closed session. Sending them as
  `captureBurst` lists (P289 test) gave 40 ms spacing for one chunk, then failed frames, extra images and an
  ImageReader overflow crash -> keep single requests, one sent per arriving frame.
- First 50 MP burst after an app start sometimes got no frame and the HAL closed the session; the 1-frame warm-up
  (P287, `WARM1`) fixed it in tests.
- 60 ms frames without OIS stalled a burst -> steady cap 40 ms; night (OIS on) up to 60 ms.
- GCam re-normalises brightness from the frames' metadata: lower ISO frames come out at the same brightness (used
  for highlight headroom, P315). Scaling our merge OUTPUT darker does stick (P313) - but clipped pixels must stay at
  white (P314 knee), otherwise lamps turn pink. Shot EV (`AeShotParams.g`) and the HDR cap change GCam's processing
  only; in a lit room (kitchen test, -0.84 EV and cap 1.5) the output was practically identical - GCam's own
  brightness target wins. 50 MP ER capture exposure = GCam's plan = viewfinder exposure (EV offset never reaches the sensor).
  `AeShotParams.g` is also called every ~200 ms for the viewfinder.
- Viewfinder surfaces on still requests -> HAL fails every frame (mixed sensor pixel modes). Viewfinder freeze at the
  shutter is the sensor mode switch; SCAMERA avoids it by running the whole session in 50 MP mode (not portable).
- GCam's exposures are 10 ms multiples (50 Hz anti-banding); ours too (`BAND`).
- RAW10 50 MP frames from this HAL in quad mode are empty (all zeros) -> RAW16 only.
- HDR ratio cap 1.5 = natural tone; 2.0 changed little on lamps (the clipping was the light sources).
- Background: GCam's ProcessReaper (`Lmpz.run`, every 10 s) killed the process in the background while our pre-merge
  ran (before GCam's ProcessingService took the shot) -> lost shots when leaving the app. Disabled in P291.
- AF: vivo's continuous-picture AF re-scans on its own (51 rescans in one log, none after a GCam trigger, mode or
  region change); continuous-video AF moves smoothly. Focus hold (AUTO while steady) works but felt unnatural.
- Final brightness is GCam's: small shot-EV offsets are masked by framing. Shadows respond to the HDR ratio cap;
  highlights to `LiveHdrMetadata.manual_ec_short` (GCam shortens the exposure, e.g. 1/25 -> 1/33 s at -0.5).
- XR remosaic (own) retired in P293: on thin high-contrast edges (branches against sky) colour error 58-64 vs ER 42.
- Merge-first (merge raw quad frames, remosaic once) loses ~13 % fine detail even with perfect alignment.
- Merge: frequency-domain merge (P288F) vs spatial merge on the phone: 16-28 % less fine noise, crisper edges,
  +0.6 s per 10-frame 25 MP merge.
- A binned raw stream (4080 x 3064/3072, RAW16) runs continuously while framing in 50 / 25 MP too -> own AE meter
  possible (P310). Indoor raw medians at GCam's exposure: ~0.02-0.03 dark rooms, ~0.07-0.09 lit kitchen.
- Probe (P307): only cameras 0 / 1 visible; 139 vendor request keys (e.g. `vivo.control.aiae.enable`,
  `vivo.control.EnableDCGHDR`, `vivo.control.EngineerRemosaicMode`), no vendor result/characteristics keys.
  AI AE (P308): no measurable effect. DCG HDR (P309): 50 / 25 MP viewfinder freezes (0-1 frames), 12 MP runs.
- Camera2 AE off is not an option (no reliable viewfinder pixels for a full own loop); the meter steers the shot.
- EXIF ISO in ER night shots is GCam's total gain (sensor ISO <= ISOCAP x digital); SR 50 MP is stock GCam exposure
  (no ISO cap, e.g. 1/16 s ISO ~7000 at night) - our request code only handles ER / SR 25 MP.
- LMC config load race (see build README): first import lost to LMC's own `apply()` - fixed P316/P317.
- LMC's Aperture button lives in a separate layout column; top-row buttons are built in `OpenPref.initFabMenu`,
  the side column (Motion, remosaic, RES) in `OpenMode.initFabMenu`. Per-mode profiles carry every pref, so UI
  switches must be kept global explicitly (P320 does it for the XML loader).

## Own exposure (P321-P330), learned 2026-11-27
- GCam brightens to its own target: shot EV, HDR cap, LMC AE modes (`pref_aemode_key`, `isoTimeParametrs` in `ohv.p`
  only redistribute time / analog / digital) and a darker merge output (mostly undone in dim rooms) do not set the
  final brightness. LMC's MaxISO setting did darken a dim shot, but GCam's plan (ISO 2400) was unchanged in the log.
- What works: the gain GCam is told per frame (`ohv.k` before `FrameMetadata.applied_digital_gain_set`, helper
  `compare(Lljm)`). 0.7 -> about +0.4 EV (P323), 2.0 in the dark -> RawR-level dark rooms (P329). The burst frames
  pass `ohv.k` while they arrive (12 calls for 10 frames); 50 MP frames report 33 ms frame duration in this mode, so
  they are matched by time window + exposure + ISO.
- P330 values: merge x 180/256 (highlight room), gain 180 lit rooms / 440 dark / daylight +0.3 EV, HDR cap 1.5 in the
  dark. Owner: "we nailed it" (dark scenes close to RawR, lit room as P323, daylight middle ground).
- Ed (RawR): do not cap analog at 800 (analog beats digital); cap the digital - which is what the reported gain does.
- "More natural / RawLens mood" tests 2026-11-27 (P331-P333, dropped, back to P330): GCam re-normalises the final
  image in lit rooms whatever we change. HDR cap 1.25 / 1.0 -> brighter overall + window clipped earlier (GCam lifts

  is captured at viewfinder TET, so long < short and GCam drops it). VHG 215 / 256 -> no change in lit rooms. A

CAUSE / CODE
P151K1's helper LMC/c2a.getC2apiPref(Lleo;) uses null argument for acquire.
An Lleo with null CaptureRequest.Builder is passed by Lksn.onClosed; the helper's CU20 reflection checks the null builder and branches to release code CU345. In K1 CU347 skips release if static Aemodef==0. The K1 re-acquisition guard at CU408 also skips new acquisition when actual key40 already reads nonzero, without necessarily recording ownership. Consequently, the release callback may occur while the process marker is zero and no write is emitted.

PATCH
From XENIUS_P151K1_KEY40_REACQUIRE_GUARD_UNSIGNED.apk; in classes2.dex method 646 LMC/c2a.getC2apiPref:
- CU347-348: replace if-eqz Aemodef -> skip with 2 NOPs. No longer skip release when owner marker is zero.
- CU415-418: replace read Aemodef and subtract1 with const/4 v10,0 + NOP padding. Release setValue(40,0) unconditionally.
This is an intentional OFF-after-close policy, NOT restoring an arbitrary value previously held by another app. The existing Lksn.onClosed callback remains intact, and only its gate helper behavior changes.

SCOPE OF PATCH
- In CameraApp.<init>, replace the original null-argument getC2apiPref() early vendor gate call with three NOP instruction units.
- In the actual camera activity's onCreate() method (CameraActivity, method_id 15526), insert const/4 v0,0 + invoke-static {v0},LMC/c2a.getC2apiPref() at method entry, ahead of the original camera activity initialization.
- Copy this 826-CU method body to a new 830-CU DEX code item, adjusting its sole try range and three handler addresses by +4 CU. Update the class_data code_off to reference the new body. Preserve original relative instructions/branches/payloads; all preexisting activity instructions remain in the same relative order.
- This avoids calling the key40 gate merely because another process (such as the crash-report process) constructs CameraApp; only the real CameraActivity calls it. Android initializes Application before Activity, so context should be available to the preexisting helper.
- LMC/c2a.getC2apiPref in classes2.dex is byte-for-byte identical to P151C FIX2. Therefore, key40 uses ORIGINAL P151C enable/restore logic (Aemodef marker, Lksn.onClosed callback). No P151H/P151I journal/refcount logic is included.
- Larb alternate Camera2 callback's missing onClosed is NOT addressed. THIS IS NOT A COMPLETE LIFECYCLE REWRITE.

NOT MODIFIED
- All other preexisting method code items including RAW50 callback, native HDR+ engine, capture frame selection, ImageReader, Image.close(), FIX2 CLEAN routine, and Xenius request helper.
- classes2.dex, all SO libraries, resources, AndroidManifest.xml, and any D35/D85 settings.

RISK / LIMITS
- Old P151C gate helper's process-local previous-value marker can still be stale following a crash. It has no durable journal/readback verification. If app crashes after key40 activation, key40 may remain globally enabled; use standalone Vivo Key40 Switch to read/reset with all cameras idle.
- The alternate Larb close path lacks a matching CameraDevice.onClosed callback, and may leave key40 enabled. We need device-log evidence to determine whether this path matters during real fullres capture.
- No Android ART runtime verifier or camera device is available here; passing DEX structure does not prove that the first/second shots or key restore work.
- This is a targeted diagnosis/fix candidate for gate activation in the wrong process, not a claim the key40 close problem is solved.

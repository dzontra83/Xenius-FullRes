ROOT-CAUSE CANDIDATE
Original classes2.dex LMC/c2a.getC2apiPref uses static Aemodef = getInfo(40) + 1
on successful acquisition, and release sets key40 = Aemodef - 1. In P151J TEST2 /
P151K0 the top-level active-marker branch was changed to recheck the real vendor
value, but the check at CU408 was 0x043a (if-ltz v4), which only skips
negative vendor values, not key40==1. A repeat acquire when key40 already 1
therefore calls setValue(40,1) and overwrites Aemodef=2, causing a later
release to restore 1.  Two closely spaced startup VIVO_GATE:1 requests in the
log are consistent with this, but the log does not contain direct Aemodef
readback, so treat this as a strong code-based cause candidate.

MINIMAL PATCH
In `classes2.dex`, method LMC/c2a.getC2apiPref, CU408:
   OLD 0x043a (if-ltz v4, +77 code units)
   NEW 0x0439 (if-nez v4, +77 code units)
When getInfo(40)==1, skip repeated acquire and preserve Aemodef original value.
When getInfo(40)==0, allow acquisition/reacquisition. The release path branches
around CU408 and is byte-identical to P151K0.

Only one executable opcode byte changed from P151K0, plus mandatory DEX
SHA-1 + Adler32 header updates. All native libs, classes.dex (including
RESOLUTION_SWITCH onResume/onStop/onClosed markers), RAW50/HDR+/DNG cleanup,
resources and manifest preserved byte-identically.
